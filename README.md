# Tiered Iron Chests

The classic chest progression — **copper, iron, gold, diamond, netherite** — rebuilt for modern Minecraft. Bigger
chests that behave exactly like the vanilla one: hoppers, hopper minecarts, droppers and comparators just work,
cats still nap on them, and upgrade kits take you from one tier to the next. No dependencies on NeoForge; Fabric API on Fabric.

- Minecraft 1.21.1 (`main`) and 1.20.1 (branch `1.20.1`), Fabric + NeoForge, one jar per loader.
- Dependencies: **NeoForge: none. Fabric: Fabric API** (its resource loader serves the jar's data/assets and its
  registry sync keeps block/item ids identical on client and server — the Fabric loader alone provides neither).
- Install on both client and server.

## Tiers

| Chest | Slots | Layout | Recipe (ring around the previous chest) | Notes |
|---|---|---|---|---|
| Copper | 27 | 9 x 3 | 8 copper ingots around a vanilla Chest | metal look, no wood |
| Iron | 54 | 9 x 6 | 8 iron ingots around a Copper Chest | a double chest in one block |
| Gold | 72 | 9 x 8 | 8 gold ingots around an Iron Chest | |
| Diamond | 108 | 12 x 9 | 6 glass + 2 diamonds around a Gold Chest | 12 columns wide |
| Netherite | 108 | 12 x 9 | 6 obsidian + 2 netherite ingots around a Diamond Chest | blast-proof (explosions never destroy it or its contents) |

Every chest is a **single block** — two tiered chests placed side by side stay two chests (no double-chest pairing;
that is deliberate, see *Design* below). Any tool breaks them (a pickaxe is fastest); the contents spill out like a
vanilla chest, the block itself drops and keeps its custom name.

## Upgrade kits

Each tier has an upgrade kit: **Wood to Copper**, **Copper to Iron**, **Iron to Gold**, **Gold to Diamond** and
**Diamond to Netherite Chest Upgrade**. Craft the kit (same ring recipe as the chest, with the previous tier's
*material* in the middle: planks, copper ingot, iron ingot, gold ingot, diamond), then put the **kit + the previous
chest** anywhere in a crafting grid to get the next tier. The kit tooltip tells you which chest it wants.

Empty the chest first: breaking it drops the contents exactly like a vanilla chest. In-place right-click upgrades
that keep the contents inside are planned for 1.1.

All 15 recipes are plain JSON in `data/tieredironchests/recipe/` (`recipes/` on 1.20.1) — overridable by data packs
and visible in the recipe book / JEI / REI / EMI.

## Vanilla parity (what "behaves like a chest" means here)

- **Automation:** every tier is a vanilla `Container` (`WorldlyContainer`, all slots from every side) — hoppers, hopper
  minecarts, droppers and any mod built on the vanilla interface treat it like a chest. On NeoForge the item-handler
  capability is registered too. Comparators read the fill level; like a vanilla chest, an obstructed chest reads 0.
- **Lid & viewers:** vanilla openers counter, open/close sounds, the 5-tick re-check, the eased lid animation.
- **Obstruction:** a solid block or a sitting cat on top keeps the lid shut; cats pick tiered chests as sitting spots.
- **Names, locks, loot tables:** custom names survive break/place, `Lock` works, `LootTable` unpacks on first open.
- **Piglins** get angry when you open one; the "Chests Opened" statistic counts it.
- **Waterloggable**, same 14/16 hitbox, rotates/mirrors in structures.

## Design

- One chest model (vanilla `ModelLayers.CHEST`), one 64x64 entity texture per tier on the vanilla chest atlas.
- One block, block entity, menu type and kit per tier; the block entity is a `RandomizableContainerBlockEntity` sized
  by tier (same base class as the vanilla chest, so hoppers/comparators/loot/lock/name are vanilla code paths).
- 12-column tiers use a custom menu/screen; the screen is composed from the vanilla `generic_54.png` nine-slice at
  runtime, so resource packs that restyle the vanilla chest GUI restyle these too. The 12x9 GUI is 276 px tall — at
  GUI scale 4 on a 1080p display that is 6 px taller than the screen (3 px clipped top and bottom); GUI scale 3 fits.
- **No double chests:** the block extends `BaseEntityBlock`, not `ChestBlock`; it has no `type` block-state property
  and never looks at neighbours when placed or updated, so vanilla's pairing logic (`DoubleBlockCombiner`,
  `ChestType`) is simply not inherited.
- **Netherite blast resistance** is the vanilla `BlockBehaviour.Properties.strength(3.0, 1200.0)` (obsidian class).
- No config file: slot counts are fixed by design; recipes are data-pack overridable.

## Building

```
.\gradlew.bat clean build
```

Jars: `fabric/build/libs/tieredironchests-fabric-<mc>-<ver>.jar`, `neoforge/build/libs/tieredironchests-neoforge-<mc>-<ver>.jar`.
Common resources (lang, models, recipes, loot tables, tags, placeholder textures) are generated by
`python tools/gen_resources.py --mc 1.21.1` (or `--mc 1.20.1` on that branch); existing PNGs are never overwritten
unless `--force-textures` is passed. Texture hand-off for artists: `art/TEXTURE-SPEC.md`.
